# Phase 5c plan: honest piece counts and lengths, fewer cheap errors

Branch `phase-5c` (from `phase-5b`; checked). Local only: nothing is pushed and no remote is touched. Baseline before any change: lint clean; API 399, worker 456, web 14 tests, all passing.

Why: Phase 5b measured that its own "possible duplicate (shared line)" rule was wrong. On job-005, 190 members sat on 105 lines; 28 lines carried more than one member (113 members) and in 111 of those the labels have different profiles spread along one long line: they look like separate beams. The rule pushed about 70 real members out of the main total (163 pieces became 93), while each member also gets the WHOLE long line as its length. Both numbers are unreliable. The frozen rule (`phase4e-v1-frozen`), its candidate selection and confidence thresholds are NOT retuned. Out of scope: pricing, weights, AISC, Tekla, computer vision, raster or outlined-text documents, automatic column detection, the column-aware schedule parser (Phase 5d), any LLM, any Bluebeam or takeoff import.

## Items (in order; commit after each; lint and all tests after each)
1. **Flaky scale-flag test.** Find the root cause of the API scale-flag test that failed twice in five runs after Phase 5b item 7 (open question 58). Loop it 50+ times alone and with the full suite, record failures, look at shared state, ordering, timing, races in the scale-confirmation code, test data collisions. Treat it as a possible production bug. Fix the cause, no retries or longer timeouts. If not found: say so, add a reproducer if possible, list what was ruled out.
2. **Shared lines: pieces and lengths.**
   a) Measure first (counts only): are shared lines made of several ORIGINAL drawn segments or one segment; where the seams are (perpendicular structural line, column-sized closed shape, grid line, nowhere); for how many of the 113 members a distinct original segment contains or lies nearest to the label's projection; whether the merge of touching collinear segments (gap 1.0 pt, offset 0.6 pt) is the cause. Write it in the results doc and stop to think.
   b) Change the semantics (reverses a 5b decision): shared-line members stay amber and grouped but their PIECES go back into the main total; their LENGTH is flagged `length_shared` and excluded from length totals, with a separate line "length not trusted (shared line)" with the piece count. Person actions (separate, merge) stay with undo. "Possible duplicate" narrows to a true duplicate candidate: same line AND same canonical profile AND the two labels overlap or are closer than 2 label heights. Only those stay outside the main total until a person decides.
   c) Only if 2a shows the seams are identifiable from the original segments: attribute a member's length to the single original segment nearest to its label's projection (`length_source = plan_geometry_segment`; candidates and rule frozen). Apply only where the seam is clear; the rest stay `length_shared`. Produce for the owner: 20 sampled job-005 members with old length, new length and an overlay image (git-ignored `fixtures/private/shots/`), plus a CSV with a blank `ok?` column. Counts only; no claim of correctness.
3. **Confirm line classes before linking.** The link job for a view does not run until a person has confirmed the structural classes (swatches, suggestion preselected, one Confirm button). The harness must confirm explicitly. A person's choice is never overwritten (keep the test). The sheet shows which views wait.
4. **Explicit sheet decisions.** Every sheet gets one explicit decision: include or exclude. Default is undecided, the page type guess is shown preselected as a guess. The link job runs only on included sheets. The takeoff and the Excel summary show "N sheets undecided" and list them; totals cover included sheets only. Decisions are sheet edits with who and when, with undo.
5. **Existing steel is listed, not dropped.** New member state "existing steel", separate from "not a member": keeps profile and (if trusted) length, outside the main total, in its own takeoff block "existing (not counted)" by sheet. "Not a member" keeps its four reasons and a small table of counts per reason. Both have undo and are in the corrections export.
6. **Docs only: `docs/TAKEOFF_COMPARE_PLAN.md`.** Wanted fields of a Bluebeam export (the format has NOT been seen; none is invented), matching method, metrics, unknowns, a timed-review protocol for an estimator. No takeoff file is read, opened or imported; files under `fixtures/private/takeoffs/` (none exist now) are left alone.
7. **Re-measure and document.** Re-run the multi-document calibration (same documents, validation-only labels, same harness): parity, color table, color mix. Re-report job-005 totals (main total pieces, `length_shared` pieces, true duplicate candidates, existing, unlinked labels, undecided sheets) against the 5b numbers (163 before, 93 after). `docs/PHASE5C_RESULTS.md`, Decision Log entries, open questions from 59; mark 48, 51, 53 and 55 answered; question 57 (schedule parser) is Phase 5d.

## Acceptance checks (all run and reported with counts)
The flaky test loop (counts of runs and failures) before and after; item 2a counts before any change; tests for the new shared-line semantics (pieces in, length out, true duplicate candidate rule, person actions with undo); a test for `plan_geometry_segment` only if 2c is done; link job refused until classes are confirmed and the harness confirms them; undecided/include/exclude tests with undo; existing steel block and not-a-member reason table tests; calibration re-run with parity against the study; lint and all tests after each item.

## Risks
1. 2c may not be supportable: if seams are not identifiable, lengths stay `length_shared` and the totals show them as not trusted. That is the honest state.
2. Putting shared-line pieces back in the main total may overcount if some are real duplicates beyond the narrow true-duplicate rule; the totals show the pieces with untrusted length separately.
3. Two explicit decisions per view and per sheet add steps for a person; the harness count of those steps is reported.
4. The scale-flag test may not reproduce; then the report says so and lists what was ruled out.
5. The owner's 20-member check is the only judge of segment attribution; nothing here grades it.
