# Phase 5t pre-registration: takeoff intake study (written BEFORE any takeoff file was opened)

Read-only study. It changes no product behavior, does not retune the frozen rule (`phase4e-v1-frozen`) or the color thresholds, imports nothing into production tables, and reads no prices or rates. Before this document was committed I had looked only at the names, sizes and types of the items in the Downloads folder (a file listing); no takeoff file was opened and no page image was viewed. Page images of the takeoff files are NOT viewed in this phase (the earlier viewing approval covers the 34 drawing PDFs only).

## Fixed in advance
**Tolerance.** Primary 6 pt. Sensitivity set: 3 pt and 12 pt, reported next to the primary and never used to choose anything. No other values.
**Frame.** Markup vertices are mapped to DISPLAYED page points with the page rotation matrix, the same frame as the reconstructed lines and the labels.
**Length markup.** An annotation of subtype Line or PolyLine with at least 2 vertices and a length of at least 3 pt. Other subtypes (count stamps, points, text, area/polygon, highlight, ink) are counted by structure but are not part of M1 to M6. If the files store length measurements in another way, I will say so and mark M1 to M6 as "not possible as specified" for those files; I will not redefine them afterwards.
**Lines and classes.** The worker's line reconstruction (`worker/src/linking/lines.py`) of the whole markup page, sheet-border lines removed; structural classes = the classes confirmed in the Phase 4e/5b study for that document and page when they exist (`structural_classes.json`), else the rule's suggestion for the whole page (and the report says which). Only text-layer vector documents that have a takeoff.
**Candidate radius** for labels: 150 pt (the frozen rule's radius).

## Measures
- **M1 coverage.** A length markup is *matched* when at least 80% of its length lies within the tolerance of ONE reconstructed structural line (measured by points sampled every 1 pt along the polyline; the line with the largest covered length is the matched line). M1 = matched / length markups, per document and pooled.
- **M2 part-of-line.** For matched markups: markup length / drawn line length. Counts per band: below 0.25, 0.25 to 0.75, 0.75 to 1.25, above 1.25.
- **M3 markups per drawn line.** For every drawn line that has at least one matched markup: the number of distinct markup annotations matched to it; distribution 1, 2, 3 or more. Reported separately for the lines our system flagged as shared (the 28 on job-005 and the shared lines of the other documents) when the document has a takeoff.
- **M4 profile availability.** Share of matched markups whose subject or contents contain a profile (the worker's profile parser, canonical form); for those, the share with a text label of the same canonical profile within 150 pt of the markup polyline (nearest-point distance to the label box). Shares only; no strings.
- **M5 length agreement.** (a) For markups with a stored measured value and a readable measurement scale: |stored - geometric| / stored, where geometric = polyline length in points x the markup's own scale; bands within 2%, 5%, 10%, beyond. (b) For matched markups with a known view scale: markup length (markup scale) against the length our system gives for the matched line (line length x the scale we confirmed for that document's study view, or the page's single scale when there is one; the production `length_shared` flag decides whether that length is trusted): bands within 2%, 5%, 10%, beyond, reported for trusted lengths and for untrusted ones separately. If scale or stored values are absent, the measure is reported as not possible and why.
- **M6 label to line, human-gold version.** For each matched markup with a profile, take the NEAREST label of the same canonical profile within 150 pt (one pair per markup). Run the frozen rule on that label with the structural lines of the page. Outcome per pair: *correct* (top-1 is the markup's matched line, endpoints within 0.6 pt), *wrong line* (the rule proposes another line), *no candidate*, and, among the not-correct ones, *right line in the top candidates* (rank 2 or 3 of the top 3) or *not among them*. Also the confidence class (high, medium, low) of each proposal. Reported per document and pooled, next to the AI-gold top-1 of Phase 4e/5b for the same documents. Each label is tagged design half, validation half, or outside the study sample (using `split.json`); the three are reported apart and nothing is chosen from them.
- **Shared lines of job-005** (28 in Phase 5b): by page and page type; with markup evidence if job-005 has a takeoff, otherwise stated as not possible. The hypothesis "they cluster on stair, isometric or section sheets" is checked by counts of shared lines per page type only.

## Classification of unmatched length markups (fixed set, first matching reason in this order)
1. **off-sheet:** a vertex lies outside the page rectangle.
2. **raster underlay:** the page is not a vector page (page kind from the scan is not vector, or one image covers at least 50% of the page).
3. **scale mismatch:** a stored measured value exists and the markup length at the scale we use differs from it by more than 10%.
4. **not on any structural line:** fewer than 80% of its length within the tolerance of any single structural line.
5. **other:** anything else (for example a markup shorter than 3 pt after mapping).
Counts per reason, per document and pooled.

## Reporting rules
Counts, shares and tables only. No comment text, no subject strings, no author names, no layer names, no file names, no client text in any document, log or chat; job ids only; the file-to-job map lives only in the git-ignored private folder. Takeoff files are copied (never moved or modified) into the git-ignored `fixtures/private/takeoffs/` and made read-only. A spreadsheet or pricing-like file is inventoried by structure only (type, number of sheets, number of rows, generic header words) and its values are never read into any document. If a measure turns out to be impossible, the report says so and why; the definitions above are not changed after results are seen.
